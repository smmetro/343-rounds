## How it works
1. Engineer signs in with Google (343sansomesf.com only). Server checks the **Users** tab and issues a 60-day session that renews whenever the app is used.
2. Phone downloads round types, last 8 values per reading, and last notes (bootstrap), and caches them.
3. Readings save on the phone as they're entered (resume works after closing Chrome).
4. Submit puts the round in an outbox on the phone (IndexedDB). The outbox sends rounds, then photos, and retries until the server has them. Duplicate sends are ignored (Round ID / Photo ID).
5. Server writes one row per round, adds cell notes, photo links, and shading; logs notes and alerts; emails alerts; fills weather for the round **start** time.

| Settings | Building Name, Alert Emails |
| Notes Log | Every note, searchable |
| Alerts Log | Every warning/alert reading |
| Photo Index | Every uploaded photo with Drive links |

### Column rules (important)
- Each reading column is tagged with the reading's **permanent ID** (hidden developer metadata), never matched by name. Two readings can share a name; renaming keeps history in place.
- Readings removed from a round move to **Retired** columns at the far right. Data is never deleted.
- New readings get a column inserted beside their section.
- Status columns are plain text so "1/2" or "100%" never become dates or numbers.

### Cell shading
- Red: ALERT (outside alert limits, or a status button styled Alarm)
- Yellow: warning
- Light blue: has a note or photo, no alert

## Editing round types
- Use the admin panel, then **Save & Publish**. Every publish saves the previous setup to Rounds > Config History; restore from **Publish History**.
- You can also edit the Templates / Log Points / Settings tabs directly. New rows typed into Log Points get an ID automatically.
- Status button styles: Neutral, Normal (green), Warning (engineer confirms), Alarm (engineer confirms + email).

## Weather
Server pulls NWS observations nearest the round start: SFOC1 (Downtown) first, SFO (KSFO) for anything Downtown doesn't report (sky, wind, sometimes humidity). Wet bulb uses the Stull approximation. If NWS is down, the round still saves and Capture Status says Failed.

How it works
- A test is a draft on the phone (saved every tap, resumes after closing). Procedure steps gate the next step and are never stored.
- Save puts the record in the outbox. Fire pumps: when sending, the phone fills the blank state form for the whole cycle (all columns so far) and sends the PDF; the server replaces the previous PDF for that cycle. Generator / Elevator: the server builds a Google Sheet and a PDF copy beside it.
- Diesel cycle = calendar month (5 week columns). Electric cycle = 6 tests; key `E<first date>`.
- Diesel can chain into electric: the diesel record is held until the electric restore is done, then both save.
- Cancel: Discard / Save as Incomplete / Keep Testing. Restore steps shown are only the ones that undo steps already done.
- Edit later: Past Tests list on the home screen. Saving an edit rebuilds the output; Drive keeps the Sheet's history, PDFs are replaced.
- Assets are fetched once per change (`testAssets`) and cached in IndexedDB (`rounds2` v2, `assets` store).

Server actions: `testSync`, `testAssets`, `submitTest` (Tests.gs). `testFormsSelfCheck` (run by hand) builds sample Generator and Elevator Sheets in Testing & Inspections > _Self-check.

If the state revises an AES form: run `tools/build_masters.py` on the new PDFs, check row lists, upload the new masters to Test Form Assets.

## Deploying changes
- **Server:** paste Code.gs > Save > run `setup` if told to > Deploy > **Manage deployments** > pencil > Version: **New version** > Deploy. Never use "New deployment" (it changes the URL).
- **App:** upload index.html / admin.html / sw.js to GitHub. Bump `APP_VERSION` in index.html so phones show the "Update" banner.
- GitHub Pages caches for up to 10 minutes.

## v1 history and bugs fixed in v2
- v1 matched Sheet columns by reading name, so duplicate names overwrote each other (Generator vs Diesel Fire Pump Heater on 97 of 102 rounds; On/Off/Auto on 9/24). v2 rebuilt history from Supabase with correct values.
- v1 notes never reached the Sheet (35 restored).
- v1 logged alerts on every keystroke (all 52 stored alerts were false; not imported).
- v1 photos were stored only in phone memory and never uploaded.
- v1 phone keyboard pushed the header off screen; v2 uses a built-in keypad.
- v1 invite emails pointed to localhost:3000 (Supabase Site URL never set); v2 has no passwords or invites.
- Apps Script "CORS" failures in May were caused by sending `Content-Type: application/json`. v2 sends `text/plain`, which browsers allow.
